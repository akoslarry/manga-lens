# MangaLens - 漫画实时翻译器

> 一款 Chrome 浏览器扩展，实时识别并翻译漫画图片中的日文文字，支持 PDF / PSD 导出

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Chrome Web Store](https://img.shields.io/badge/Chrome-Extension-green)](https://chrome.google.com/webstore)
[![TypeScript](https://img.shields.io/badge/TypeScript-5.0-blue)](https://www.typescriptlang.org/)
[![Vite](https://img.shields.io/badge/Vite-5.0-brightgreen)](https://vitejs.dev/)

## 功能特性

### 核心翻译管线

| 功能 | 说明 |
|------|------|
| **腾讯云 OCR** | 支持通用印刷体、高精度版、手写体、英文四种识别模式 |
| **DeepSeek V4 Pro 翻译** | 智能日→中翻译，上下文感知 |
| **并发控制** | OCR 队列（3并发）+ 翻译队列（5并发），10 任务上限自动暂停 |
| **对话合并** | 基于距离聚类的智能分组算法，竖排/横排自适应方向检测 |
| **四角锚点** | 8 点锚点自动检测图片旋转并校正坐标 |
| **RTL 支持** | 日漫从右往左阅读模式 |
| **本地翻译缓存** | IndexedDB 持久化存储，刷新页面无需重新调用 API，节省 Token |

### PDF 导出编辑

| 功能 | 说明 |
|------|------|
| **字体自适应** | 按气泡尺寸与字数自动计算字号（算法 v1，见下文） |
| **溢出视觉提示** | 译文超出气泡时显示橙色角标与描边，提示手动调整 |
| **进入导出模式** | Popup 一键进入编辑态 |
| **双击编辑文字** | 双击覆盖层直接修改翻译文本 |
| **拖拽移动** | 拖拽覆盖层调整位置 |
| **缩放手柄** | 四角拖拽调整覆盖层尺寸 |
| **字号调节** | 单个覆盖层独立字号设置 |
| **透明度控制** | 独立调节覆盖层透明度 |
| **删除覆盖层** | 移除不需要的翻译气泡 |
| **工具栏** | 选中覆盖层弹出编辑工具栏（字号/透明/删除） |
| **PDF 导出** | jsPDF + html2canvas 合成 PDF，支持自定义保存子目录 |
| **退出自动保存** | 退出时自动持久化所有编辑到本地缓存 |

### PSD 导出（v1.7.0 新增）

面向需要在 Photoshop 中**二次精修译文**的场景，导出为图层完整、文字可编辑的 PSD。

| 功能 | 说明 |
|------|------|
| **原图背景层** | 原图作为最底层「原图」图层一并导出，打开即可见完整效果，无需手动拖入 |
| **可编辑文字层** | 每个译文气泡导出为独立文字图层，双击即可改字、改字号 |
| **竖排/横排自适应** | 按 `MergedDialog.isVertical` 写入 `orientation`，PS 中方向正确 |
| **段落框** | 使用 `shapeType: 'box'`，可在 PS 中拖动/缩放文本框 |
| **底衬色块** | 译文背景导出为独立纯色图层，保留用户设定的透明度 |
| **所见即所得定位** | 几何直接量自页面 DOM 实测矩形，与网页端渲染完全一致 |
| **批量导出** | 「PSD(全部)」/「PSD(选中)」两个入口，按勾选范围逐张导出 |
| **自动分目录** | 同批次统一放入以时间戳命名的文件夹，文件名为 `时间戳_序号.psd` |

## 安装部署

### 前置要求

- Node.js 18+
- npm
- Chrome 浏览器

### 安装步骤

```bash
# 1. 克隆项目
git clone https://github.com/akoslarry/manga-lens.git
cd manga-lens

# 2. 安装依赖
npm install

# 3. 构建扩展
npm run build

# 4. 加载扩展
#    - 打开 Chrome，访问 chrome://extensions/
#    - 开启"开发者模式"
#    - 点击"加载已解压的扩展程序"
#    - 选择项目中的 dist/ 目录
```

### 开发模式

```bash
npm run dev     # 启动开发服务器（热重载）
npm run build   # 构建生产版本
```

打开扩展 popup 界面（点击扩展图标），配置以下选项：

|--------|------|------|
| **翻译开关** | 开启/关闭翻译功能 | 是 |

| **腾讯云 SecretId** | OCR API 身份标识 | 是 |
| **腾讯云 SecretKey** | OCR API 密钥 | 是 |
| **腾讯云地域** | 如 ap-guangzhou | 是 |
| **OCR 模式** | 高精度/基础/手写体/英文 | 是 |
| **字号缩放** | 全局字号缩放比例（50-160%），对所有气泡等比缩放。实际字号由自适应算法按气泡尺寸决定，此项为整体系数，不破坏气泡间相对大小 | 默认 100% |
| **单次翻译上限** | 每批次最大图片数（1-100）| 默认 30 |

### API 密钥获取

**腾讯云 OCR**：访问 [腾讯云控制台](https://console.cloud.tencent.com/cam/capi) → 创建子用户并授权 `QcloudOCRFullAccess` → 获取 SecretId/SecretKey → 开通 [通用文字识别（高精度版）](https://console.cloud.tencent.com/ocr/overview)。

**DeepSeek 翻译**：访问 [DeepSeek 控制台](https://platform.deepseek.com/api_keys) → 创建 API Key → 填入扩展配置或设置环境变量 `DEEPSEEK_API_KEY`。

## 核心模块说明

### 1. content-script.ts — 内容脚本主入口

漫画页面的图片检测、OCR 排队、翻译渲染、PDF 编辑模式的全部调度中心。

**并发控制机制**:

```
OCR 队列:     9 并发
翻译队列:     999 并发（实际不设限）
单次批次上限: 默认 30 张/次（可在 Popup 中配置 1-100）
```

**单次翻译上限的准入闸门（v1.6.0 修复）**

历史上存在「设置 30 张却翻译到 30+ 才停止」的问题，根因是四者叠加：

| # | 因素 | 说明 |
|---|------|------|
| A | 计数时机滞后 | 计数在 `translateAndRender` **完成之后**执行，上限判断天然滞后一个 API 往返时长 |
| B | 翻译并发近乎无限 | `TRANSLATION_CONCURRENCY = 999`，且 OCR 每完成一张就立即点火翻译，飞行任务持续累积 |
| C | 守卫仅在函数入口 | `isTranslationPaused` 只在函数入口检查，无法阻止已进入 `await` 的任务 |
| D | 飞行任务继续计数 | 已在途的任务完成后仍执行 `++`，逐个把计数推高 |

最终计数 = `上限 + 触发暂停瞬间的飞行任务数`，超额幅度取决于 API 耗时与 OCR 速度之比。

**修复方案：双闸门 + 准入前置**

| 闸门 | 位置 | 判断口径 |
|------|------|---------|
| **翻译层硬闸门** | `processNextTranslation` 启动任务**之前** | `已完成 + 在途 ≥ 上限` → 置暂停 + 弹窗（仅一次），不启动新任务 |
| **OCR 层软闸门** | `processNextOCR` 启动任务之前 | `已完成 + 在途 + 待翻译 ≥ 上限` → 停 OCR，待翻译消化后自动恢复（不置暂停标志） |

关键点：判断移到**任务启动前**，超额窗口从「一个 API 往返时长」缩小为 **0**。

其他配套修复：
- 弹窗增加 `hasShownLimitPopup` 标志，避免飞行任务逐个完成时反复弹出
- 翻译完成后同时点火 `processNextOCR()`，让 OCR 软闸门能随翻译消化而自动解除
- 弹窗文案补充「另有 N 张正在收尾」，避免用户困惑于计数未达上限却提示已到上限
- **修复上限未持久化加载**：`maxImagesPerBatch` 此前始终以硬编码 30 启动，仅在打开 popup 保存时才更新，刷新页面后会静默失效

**消息类型**:

| 消息 | 来源 | 功能 |
|------|------|------|
| `TOGGLE_ENABLED` | Popup | 开关翻译 |
| `CONFIGURE_API` | Popup | 更新 API 配置 |
| `REFRESH` | Popup | 刷新页面翻译 |
| `SELECT_IMAGE` | Popup | 手动选择图片 |
| `GET_STATUS` | Popup | 获取处理状态 |
| `ENTER_PDF_MODE` | Popup | 进入 PDF 导出编辑模式 |

### 2. background.ts — Service Worker

API 请求中转，解决浏览器跨域限制。核心能力：图片 URL→Base64 转换、腾讯云 OCR 签名请求（Base64 及 URL 两种模式）。

### 3. dialog-merger.ts — 对话合并

距离聚类算法将 OCR 碎片合并为完整对话。

**合并流程**：预处理（边界计算 + 竖排/横排判断）→ 分离方向 → 按行/列分组 → 组内排序（竖排按Y、横排按 RTL 规则）→ 距离阈值合并。

### 4. translation-cache.ts — 本地翻译缓存

基于 IndexedDB 的持久化翻译缓存。刷新页面时直接读取缓存渲染，避免重复调用 OCR/翻译 API。在 PDF 编辑模式下自动同步用户修改（文字/位置/字号/透明度/删除）。

### 5. export-pdf.ts — PDF 导出编辑引擎

完整的所见即所得编辑系统：

- **选择系统**：点击选中覆盖层，边框高亮 + 缩放四角手柄
- **文本编辑**：双击覆盖层进入文字编辑模式
- **拖拽移动**：选中后拖拽平移覆盖层位置
- **缩放手柄**：四角拖拽缩放覆盖层尺寸
- **工具栏**：选中后弹出浮动工具栏（字号调节/透明度滑块/删除按钮）
- **PDF 合成**：jsPDF + html2canvas 渲染整页为 PDF
- **自动保存**：退出时自动持久化所有编辑到 IndexedDB 缓存

### 6. export-psd.ts — PSD 导出引擎

把「当前页面已翻译的图片」导出为 Photoshop 可编辑的 PSD。

**数据源**

明确规定为**当前页面中已翻译的图片**（`getAllTranslatedImages()`），
而非本地缓存里的全部条目 —— 缓存可能残留大量历史记录，导出它们既慢又无意义。

**图层结构**（每组译文两个图层，自下而上）

```
原图                      ← 最底层背景，铺满画布
  底衬_N                  ← 纯色矩形，承载用户设定的透明度
    文本_N                ← 段落框文字层，可编辑/可拖动缩放
```

> ⚠️ **图层顺序约定**：`ag-psd` 的 `children` 数组是**靠后元素在上层**。
> 因此构造顺序为「原图 → 底衬 → 文字」，数组末位是文字层。

**关键实现要点**

| 要点 | 说明 |
|------|------|
| **几何取自 DOM** | 覆盖层的 `left/top/width/height` 百分比以**覆盖层容器**为基准（而容器可比图片宽 3 倍以上），且含图片在容器内的偏移。直接乘图片尺寸会导致整体放大/偏移，因此改为读取页面实测矩形后换算 |
| **文字层需占位 canvas** | `ag-psd` 的 `getLayerDimentions()` 只从 `canvas`/`imageData` 取尺寸。文字层若无 canvas，图层矩形会被压成 0×0，PS 中看不到文字。故为每个文字层附加一张**全透明、与之等大**的占位 canvas |
| **transform 必须带位移** | PS 计算文字落点用 `transform` 的 `(tx,ty)`。若恒为 0，文字会堆在图层左上角。此处写入图层左上角坐标 |
| **`bounds` 用相对坐标** | 实测 Adobe 样本：`bounds` 以 `transform` 锚点为基准，非画布绝对坐标。且 `ag-psd` 要求分量为 `{units,value}` 形式 |
| **必须保留 1px 透明像素** | `ag-psd` 依据 `hasAlpha()` 决定是否写透明通道；纯不透明图层不写透明通道，会导致 PS 中该层被撑满画布。故底衬与原图均清空右下角 1px |
| **跨域回退** | 原图跨域受限（canvas 被污染）时自动省略原图层，仅导出文字层 + 底衬，不使整个导出失败 |

**命名与目录**

同一批次统一放入以**批次时间戳**命名的文件夹，每张图片一个独立 PSD：

```
下载目录/
  └─ 2026-09-28-10-45-12/
       ├─ 2026-09-28-10-45-12_001.psd
       ├─ 2026-09-28-10-45-12_002.psd
       └─ ...
```

- 时间戳格式 `YYYY-MM-DD-HH-mm-ss`（**本地时间**，非 UTC；冒号替换为短横线以适配 Windows 文件名）
- 序号固定 3 位（`001`）保证目录内排序稳定，超过 999 自动扩位
- 实现方式：把文件夹名拼进 `chrome.downloads.download` 的 `filename` 相对路径，由浏览器自动创建目录
- ⚠️ 若 Chrome 开启了「下载前询问每个文件的保存位置」，子目录会被忽略并弹出另存为对话框

### 7. ocr-engine.ts — OCR 引擎

腾讯云 OCR 调用与四角锚点机制。在图片四角及四边中点添加 8 个锚点标记，OCR 识别锚点后对比预期位置检测旋转角度，校正所有文字坐标。

### 8. font-fitter.ts — 字体自适应计算（算法 v1）

解决「大框小字」「小框溢出」两类问题，同时保留原文的视觉分级。

**设计目标**：
- 超大气泡 + 少数字（标题/拟声词）→ 字号应足够大，填满空间
- 超小气泡 + 大量文字（小字说明）→ 优先保证不溢出，但不得低于可读下限
- 保留原文的相对大小对比（拟声词大、说明文字小），不因翻译而抹平

**四步计算流程**：

| 步骤 | 说明 |
|------|------|
| **1. 几何适配** | 由框宽高与译文字符数解析求解「刚好填满」的字号。按字符组成估算平均宽度比（全角≈1、半角≈0.55），用二分法逼近满足 `行数 × 字号 × lineHeight ≤ 可用高度` 的最大字号 |
| **2. 视觉分级** | 取 OCR 得到的原文实际字符高度（竖排取片段宽度、横排取片段高度的中位数），与几何解加权融合（默认原文权重 0.6），避免拟声词被撑爆、小字说明喧宾夺主 |
| **3. 约束** | 施加 `fillRatio`（默认 0.88，留呼吸空间）与 `[minFontSize, maxFontSize]` 区间。字号不得低于可读下限 |
| **4. 迭代收敛** | 元素入 DOM 后，以浏览器真实排版为权威，测量 `scrollHeight` vs `clientHeight`，按 0.9 / 1.06 系数迭代修正（最多 6 次），解决中英混排、标点避头尾、字体度量等公式算不准的问题 |

**溢出处理策略**（重要设计决策）：

> **不自动扩大文本框。** 自动扩框会让用户失去原始位置参考，且粗略阅读时必须进入编辑模式才能重新看到画面。因此采用**视觉提示**：溢出时给覆盖层加橙色描边 + 右上角 `⤢` 角标 + tooltip 说明，由用户决定是否手动调整。

**溢出提示与 PDF 编辑模式的关系**：

- 角标与描边均为 `pointer-events: none`，是**纯视觉标记**，不具备点击功能；非编辑模式下覆盖层本身也不接收事件（点击穿透到原画），因此不会误触
- 描边用 `box-shadow` 而非 `outline` 实现，以避免与编辑态的蓝色选中 `outline`（`2px solid #667eea`）互相覆盖，也避免退出编辑时被清空
- **人工调整即撤下**：在 PDF 模式下拖拽缩放或移动文本框后，**直接撤下溢出提示，不做复检**
  - 设计理由：用户手动调整代表其已知意图，系统无需再评判结果。若复检，则「故意缩小文本框」的场景下标记将永远无法消除，与用户意图对抗
  - 被人工调整过的对话会记入内部集合，后续重新渲染也不再为其添加溢出标记

**字号的三层结构**（职责独立，互不冲突）：

| 层级 | 控制者 | 作用范围 | 职责 |
|------|--------|---------|------|
| **① 自适应基准字号** | `font-fitter` 算法 | 每个气泡独立 | 按气泡尺寸与字数计算，**决定气泡间的相对大小（视觉分级）** |
| **② 全局缩放倍率** | popup「字号缩放 (%)」，持久化 | 所有气泡 | 整体等比缩放，100% = 不改变自适应结果 |
| **③ 图片级缩放** | 角标 `−` / `+` 按钮，仅当次会话 | 单张图片内所有气泡 | 对某张图做临时微调 |

最终字号 = `①  ×  ②  ×  ③`，并受可读下限（10px）约束。由于 ② ③ 是**乘性系数**而非绝对值，放大缩小时各气泡仍保持自身的相对大小，视觉分级不会丢失。

**迭代收敛与用户缩放的边界**：

迭代收敛**仅在 ② ③ 均为 100% 时执行**。原因：用户调大缩放的目的就是「字大一点，哪怕略微溢出」，若此时仍做迭代收敛，算法会把字号压回「刚好装下」，反而抹掉用户意图。用户一旦调整过缩放，即直接采用公式解 × 缩放，不再二次修正（但仍会判定溢出状态用于提示）。

**设置项语义迁移**：

早期版本存储的是「基础字号 px」（`mangaLensFontSize`，22px 为默认）。算法 v1 起改为「缩放倍率」（`mangaLensFontScale`，1.0 = 100%）。读取时优先取新字段；若只有旧字段，则按 `px / 22` 换算为倍率，避免用户设置丢失。保存时同时写入两个字段以兼容不同版本读取。

**版本号与缓存迁移**：

`MergedDialog.fontSizeVersion` 记录该条目使用的算法版本（当前 `FONT_SIZE_ALGO_VERSION = 1`）。读取本地缓存时：
- 若版本缺失或低于当前版本 → 触发**自动迁移**：更新版本标记并回写缓存
- 字号本身不持久化（渲染时实时计算），因此迁移无需改动对话数据，用户的手动调整（`customFontSize` 等）会被完整保留

版本历史：

| 版本 | 算法 |
|------|------|
| 0 / 缺失 | 旧算法：仅按「译文字数 / 原文字数」比例缩放，不感知框尺寸 |
| 1 | 几何适配 + 视觉分级 + 迭代收敛 + 溢出检测 |

## 使用方法

### 基础操作

1. **配置 API**：点击扩展图标 → 分别配置翻译 API 和 OCR 设置 → 保存并测试连接
2. **开启翻译**：打开右上角开关，页面自动开始处理漫画图片
3. **手动选择**：点击"手动选择图片或重新翻译" → 点击页面上的目标图片
4. **刷新翻译**：点击"刷新页面翻译"按钮

### PDF 导出流程

1. 等待所有目标图片翻译完成
2. 点击 Popup 中的「进入PDF导出模式」
3. 在编辑模式下调整覆盖层：双击改文字、拖拽改位置、缩放改大小、工具栏调字号/透明度
4. **随时点工具栏「💾 保存」**：立即持久化改动到本地缓存，且**停留在编辑模式**继续调整
5. 点击「❌ 退出」：若无未保存改动则直接退出；若有则弹窗询问「保存 / 恢复」
6. 下一次进入同一页面时，编辑结果会从缓存直接加载

> 编辑文字时使用 `Ctrl+V` 粘贴会自动剥离源格式（只保留纯文本），确保文本框内字号统一。

### PSD 导出流程（v1.7.0）

前提：处于 PDF 导出编辑模式，且目标图片已完成翻译。

1. 在工具栏点击 **🎨 PSD(全部)** 导出所有已翻译图片，或先勾选部分图片再点 **🎨 PSD(选中)**
2. 导出前会自动静默保存当前编辑（保证导出的内容与所见一致）
3. 浏览器下载目录下生成以时间戳命名的文件夹，内含每张图片对应的 PSD
4. 用 **Adobe Photoshop** 打开，图层结构为：

```
原图            （背景）
  底衬_0         （白色色块，可调透明度）
    文本_0       （文字层，双击可改字）
  底衬_1
    文本_1
  ...
```

**PS 中的可操作项**

| 操作 | 说明 |
|------|------|
| 双击文字层 | 直接修改译文、字号、字体 |
| 拖动文本框 | 点击文字层后拖动调整位置 |
| 缩放文本框 | 拖动变换框四角调整尺寸 |
| 切换方向 | `文字 → 文字方向 → 垂直/水平` 可手动切换 |
| 调底衬 | 单独调整 `底衬_N` 图层的不透明度 |

> ⚠️ **建议使用 Adobe Photoshop 验证效果。** Photopea 等 Web 版实现有自己的文字引擎与私有字段约定，对 `ag-psd` 生成的文件结构容错性较差，可能出现竖排失效或异常，不代表 Adobe PS 的实际表现。

## 常见问题

**Q: OCR 识别不准确？**
检查图片清晰度，漫画推荐使用「高精度识别」模式。锚点机制会自动检测和校正旋转。

**Q: 翻译很慢？**
检查网络连接和 API 配额。翻译瓶颈通常在 DeepSeek API 响应速度，OCR 3 并发可充分并行。

**Q: 如何卸载扩展？**
打开 `chrome://extensions/`，找到 MangaLens，点击"移除"。

**Q: 退出 PDF 模式后编辑丢失？**
v1.1.0 起退出时自动弹窗确认并持久化。选择"保留修改"即写入本地缓存，刷新页面不丢失。

**Q: 导出的 PSD 里文字显示为横排（或竖排失效）？**
请使用 **Adobe Photoshop** 打开。Photopea 等 Web 版 Photoshop 使用自研文字引擎与私有字段约定，对 `ag-psd` 生成的文件容错性较差，表现与 Adobe PS 不同。

**Q: 导出的 PSD 中没有原图层？**
原图来自跨域站点且未返回 CORS 头时，浏览器会阻止读取像素（canvas 被污染）。此时会自动省略原图层，仅导出文字层 + 底衬。可在控制台搜索 `原图无法写入 PSD` 确认。

**Q: PSD 导出没有生成文件夹，直接平铺在下载目录？**
Chrome 若开启了「下载前询问每个文件的保存位置」，子目录路径会被忽略。可在 `chrome://settings/downloads` 关闭该选项。

- **新增「💾 保存」按钮**：位于工具栏「退出」左侧，点击即持久化当前所有修改到本地缓存，**不退出** PDF 编辑模式，按钮短暂显示「✅ 已保存」反馈
  - 修复隐藏缺陷：双击编辑文字时原先**没有 `input` 监听**，纯文字修改不会置 `pdfModeEditDirty`，导致退出前的静默保存被跳过（存在丢修改风险）。现已补齐
  - 退出弹窗条件优化：保存后**无新修改**时点「退出」直接退出不弹窗；保存后**又有修改**时才正常弹窗
- **文字编辑统一字号**：双击编辑时拦截粘贴事件，强制纯文本粘贴（`text/plain` + `execCommand('insertText')`），并对内容做规范化——移除所有富文本标记，只保留纯文本与 `<br>` 换行
  - 修复现象：从 22px 文本框复制到 20px 文本框时，源内联 `font-size` 会覆盖当前字号，导致同一框内出现两种字号
- **图片适配修复**：拖入浏览器的图片（blob: / file: URL）此前导出为空白
  - `blob:` URL 改在 content-script 侧 `fetch` 后转 dataURL（background 无法访问页面创建的 blob）
  - **`file://` 图片改为「复用页面上已加载的 `<img>` 元素」截图**
    - 根因：Chrome **明令禁止对 `file:` 协议发起 fetch/XHR**——协议白名单仅含 `chrome, chrome-extension, chrome-untrusted, data, http, https, isolated-app`，`file:` 不在其中。因此新建 Image 重新请求或 fetch/XHR 均必然失败，且会使画布被判定污染
    - 解法：页面中的 `<img>` 像素已由浏览器加载完成，直接 `ctx.drawImage(已加载元素, 0, 0)` 即可导出，与 OCR 提取图片的机制一致
    - ⚠️ 关键：**绝不设置 `crossOrigin`**——一旦设置会以 CORS 模式重新请求，反而主动触发画布污染
  - 图片转 dataURL 的完整路径优先级：`data:` 直用 → `blob:` fetch → `file:` 复用已加载元素 → 同源 fetch（失败回退 XHR / canvas）→ 跨域交给 background
  - 绘制后主动探测 canvas 污染，提前抛出明确错误而非静默空白
  - 导出失败**如实告知**：列出失败页序号与原因（原先仅 `console.error` 静默跳过）
  - PDF 文字绘制改用 `dataset.mlPlainText`，避免溢出角标 `⤢` 被画进 PDF
  - ⚠️ **前置条件**：在 `file://` 页面使用需在 `chrome://extensions` 中为本扩展开启「允许访问文件网址」（`<all_urls>` 不包含 `file://`）

- **退出自动保存**：修复退出时不触发保存的 bug（缩放未标记脏数据 + 退出前条件跳过），确保编辑结果持久化
- **本地翻译缓存**：IndexedDB 持久化管理，支持启用/禁用开关
- **单次翻译上限**：可配置批次最大图片数
- 移除 Hugging Face 本地 OCR 依赖，统一使用腾讯云 OCR

- 实现 OCR/翻译双队列并发控制
